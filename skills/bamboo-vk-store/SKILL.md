# Магазин ВК

Читайте docs/VK_STORE.md и docs/PUBLISHING_POLICY.md. CLI: python bamboo.py vk ...;
MCP vk_*. Ключ хранится вне проекта; не просить секреты и callback в чате.

1. Сохранить точное поручение, проверить status/check и прочитать нужный объект.
   Реальные ID брать из ответа. Название не доказывает материал или назначение.
2. Для нового поста подготовить пакет через bamboo-content и bamboo-review. Прямое
   «напиши и опубликуй» исполнять через vk publish SLUG --request "..." --execute или
   vk_publish. Без ручной анкеты; текст/фото и назначение всё равно проверяются.
3. Для конкретного изменения цены, описания, параметров или существующей записи:
   read → plan → проверка before/params → apply → сверка. При ясном поручении в указанном
   объеме не задавать второй вопрос. Хеш confirmation — контроль версии плана.
4. Для неоднозначного удаления, чужого объекта, нового бюджета или неуказанного массового
   изменения уточнить границы, не выводить разрешение из общего «управляй магазином».
5. Сохранять объем, размеры, материал, уход, состояние, вложения, если изменение их
   не запрошено. Не заносить товар в другую категорию только по поэтическому названию.
6. Независимый рецензент при наличии проверяет план; роли не подделывают человеческие
   подписи. Если независимый запуск недоступен, обозначить последовательную проверку.
7. Успех только после verified. При uncertain/sending/unverified/conflict выполнить
   reconcile и сообщить состояние; не создать эквивалентный новый план вместо сверки.

Технические ограничения API и отсутствие авторизации не обходятся. Нативные статьи ВК,
личные сообщения, платежи и рекламные кабинеты не становятся доступными от наличия скилла.
Это не повод отказываться от поддерживаемой публикации, на которую есть прямое поручение.
