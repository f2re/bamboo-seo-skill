# bamboo-analytics

Прочитайте docs/ANALYTICS.md и docs/COMMERCE.md. Вход: доступные даты, права на сайт и выгрузка CSV/API.
Без авторизации работать с предоставленным файлом; не придумывать трафик и продажи.

Координатор запускает analytics-pull для выбранного источника или analytics-import с явным
путём, затем analytics-report. Проверить coverage, даты, детализацию и пропуски.
Google page_query не прибавлять к page: использовать его отдельным слоем для запросов и
кандидатов на несколько URL. Яндекс собирает URL и QUERY отдельно; в grain=query page_hint
означает только popular complementary URL и не является полным распределением query×page.
Отсутствие строки не означает ноль. Conversion показывать отдельно и связывать с поиском
только при явной атрибуции источника. Не смешивать просмотры, клики, пользователей, лиды,
выручку, прибыль и условную экономию.

Передать отчёт bamboo-analyst. Он возвращает ограничения, максимум три гипотезы, исходный
показатель, необходимую проверку, следующее действие и критерий отмены. Для малой выборки
предложить накопить данные. Не обещать причинность по сравнению двух недель и не удалять
статью по отсутствию показов. Затраты на редактора, модель и фото учитывать отдельно,
не говорить «привлечение бесплатно» только потому, что нет рекламного кабинета.

Предложения записать отдельно от действующей стратегии. Изменение content/strategy.md,
публикации, системных инструкций и расписания требует решения владельца.
Выход: измеренный результат, его границы и один ближайший обоснованный эксперимент.
