# Bamboo SEO Skill

Текущая версия: **1.3.0**.

Редакционный инструментарий Bamboo Pottery для **Codex, Claude Code и Google Antigravity**.
Не фабрика SEO-страниц: фактура мастера и настоящие фотографии превращаются в проверяемый
контент-пакет — статью, пост ВКонтакте, карточку изделия, сторис, карусель и ответы на вопросы.

**Python 3.10+; только стандартная библиотека.** Нет Docker, сервера моделей, базы в облаке,
сторонних Python-зависимостей и автоматической установки программ.
Текст пишет выбранный вами ИИ в его рабочей среде. Python создаёт задания, проверяет данные,
фиксирует утверждение, экспортирует материалы, работает с WordPress, VK API и собирает аналитику.
Сам по себе скрипт не вызывает платную модель и не имитирует её работу.

## Живые публикации, а не одинаковые полотна

[Стили постов и статей](docs/PUBLICATION_STYLE.md) · [Прямой выпуск](docs/PUBLISHING_POLICY.md) ·
[Разбор текущей ленты и статьи](research/editorial/audit-2026-10-09.md) · [Новые примеры](examples/editorial/README.md).
Девять профилей: деталь, ответ, сравнение, процесс, предложение, длинный пост,
практическая статья, история и исследование. Минимум 800 знаков/слов снят.
`style-check` оценивает читаемость; фотографии встраиваются по смыслу, выделения работают.

Поручение «напиши и опубликуй пост» выполняется без ручной анкеты и второго подтверждения:

```sh
python bamboo.py validate first-post
python bamboo.py export first-post
python bamboo.py vk publish first-post --request "Напиши и опубликуй пост о выборе пиалы в Bamboo Pottery" --execute
```

Без `--execute` сеть не вызывается. Соединение настраивается один раз ниже. Ошибки фактов,
отсутствие доступа и неизвестный результат отправки не скрываются. Это технические причины,
не запрет публикации. Новый путь не подменяет родную статью ВК длинным wall.post.

## Управлять магазином ВК через агента

Навык `bamboo-vk-store` управляет товарами, фотографиями, подборками, публикациями и
поддерживаемыми настройками сообщества. Есть CLI и локальный MCP-сервер с 11 инструментами.
Координатор читает магазин → проверяет конкретные изменения → исполняет прямое поручение
владельца → сверяет результат. Повторное согласование обычной публикации не требуется.
Пароль аккаунта агенту не передаётся; ключ хранится вне репозитория.

```bash
# 12345678 замените ID своего приложения с разрешёнными правами VK API:
python3 bamboo.py vk init --community bamboopottery --client-id 12345678
python3 bamboo.py vk login
python3 bamboo.py vk check
python3 bamboo.py vk sync
```

После подключения скажите агенту:

> Используй bamboo-vk-store. Покажи товары магазина, найди нужную чашу и подготовь
> изменение цены на 2700 рублей. Другие поля не меняй. Сначала покажи план.

Локальный домен, внешний сервер и sudo исполнителю не нужны. Возможность localhost и
прав wall/market должна быть разрешена ВК для вашего приложения; успешный вход не
доказывает права записи. Есть импорт уже полученного пользовательского ключа.
`vk apply` без `--execute` ничего не отправляет. Неопределённый ответ блокирует повтор.
Платежи, личная переписка, заказы и смена владельца не реализованы.

## Простой рабочий сценарий

Для работы с ВК не нужны собственный сайт, GSC или Яндекс. Достаточно Python 3.10+,
разрешённых фактов мастера и реальных фотографий. Не начинайте с десяти товаров: пройдите
один пост целиком. Подробно: [первый рабочий материал](docs/START.md).

```bash
python bamboo.py init
python bamboo.py doctor --text
python bamboo.py new first-post --topic "Ваша тема" --formats vk
```

`doctor --text` показывает недостающие данные и следующий шаг; без флага сохраняется JSON.
`new` по умолчанию готовит один пост ВК, не четыре формата сразу. Факты и текст заполняются
в выбранном ИИ; Python не сочиняет вместо модели и не подставляет придуманные характеристики.

Когда есть реальная выгрузка, достаточно:

```bash
python bamboo.py analytics-import --file your-metrics.csv
python bamboo.py analytics-report
```

`analytics/report.md` начинается с максимум трёх проверяемых действий по существующим страницам.
`--end` можно не указывать: берётся последняя дата в базе. Данные не выдаются за свежие на сегодня;
при нехватке измерений вместо совета изменить страницу выводится причина. Для расширенного
CSV Яндекса используйте `analytics-yandex-import`, а не универсальный импорт.

## Начать в репозитории

```bash
git clone https://github.com/f2re/bamboo-seo-skill.git
cd bamboo-seo-skill
python3 bamboo.py init
python3 bamboo.py doctor
python3 bamboo.py new first-bowl --topic "Как выбирать чашу по фотографиям" --formats article,vk,stories --audience A
```

В Windows используйте `py -3` вместо `python3`. В примерах далее `python` означает Python 3.10+.
Откройте эту папку в выбранном ИИ. Нативные адаптеры уже находятся в репозитории:
повторная установка в эту же папку не нужна.

Задание агенту:

> Используй bamboo-content для first-bowl. Сначала проверь brief и источники. Собери недостающие
> вопросы мастеру одним сообщением. Не придумывай параметры изделия. Делегируй проверку фактов,
> голоса и поискового намерения отдельным доступным агентам. Подготовь пакет и превью,
> но не утверждай и не публикуй его.

`new` создаёт **незаполненный** бриф, а не готовую статью. Внешние факты и характеристики
нужно подтвердить. Неполное задание намеренно не проходит `validate`.

## Установить в существующий проект

Из каталога этого репозитория:

```bash
python bamboo.py install --target ../bamboo-work --systems all --dry-run
python bamboo.py install --target ../bamboo-work --systems all
cd ../bamboo-work
python bamboo.py init
python bamboo.py doctor
```

Доступны `--systems codex`, `claude`, `antigravity` или список через запятую.
Установка проектная, без `sudo` и без правок домашнего каталога. Код копируется в
`.bamboo/toolkit`, добавляется локальный `bamboo.py`. AGENTS.md, CLAUDE.md и GEMINI.md
сохраняются: в них добавляется только маркированный блок. Конфликтующий пользовательский
файл не перезаписывается. Повторный запуск обновляет неизменённые управляемые файлы;
резервные копии сохраняются в `.bamboo/backups/`.

```bash
python bamboo.py uninstall --dry-run
python bamboo.py uninstall
```

Удаление сохраняет изменённые пользователем файлы, контент, аналитику и резервные копии.
Изменение выбранных систем не удаляет ранее установленные адаптеры: для удаления используйте uninstall.
После установки перезапустите сессию ИИ или обновите список скиллов в его интерфейсе.

## Скиллы и роли

| Скилл | Результат |
|---|---|
| `bamboo-plan` | Реестр тем, приоритеты, вопросы мастеру, проверка дублирования намерения |
| `bamboo-research` | Источники и связанные с ними проверенные утверждения |
| `bamboo-content` | Полный редакционный процесс и несколько форматов одного материала |
| `bamboo-review` | Автоматическая проверка плюс отдельные отчёты редакторов |
| `bamboo-publish` | Превью, проверка разрешения и явная публикация |
| `bamboo-analytics` | Импорт метрик, сравнение периодов, предложения изменений |
| `bamboo-vk-store` | Управление магазином ВК: чтение, план, подтверждение, запись и сверка |

Шесть ролей: `bamboo-researcher`, `bamboo-factcheck`, `bamboo-editor`, `bamboo-seo`,
`bamboo-analyst`, `bamboo-vk-reviewer`. Они работают на чтение и возвращают отчёты координатору.
До трёх параллельных задач, без рекурсивного размножения агентов; два цикла исправлений,
затем нерешённые вопросы владельцу. Запускать их должен механизм субагентов выбранной среды.
Если его нет, используется последовательный разбор с явным указанием этого ограничения.

## Проверка и опциональная ручная вычитка

```bash
python bamboo.py validate first-bowl
python bamboo.py export first-bowl
python bamboo.py review-template first-bowl
python bamboo.py status first-bowl
```

`export` создаёт `exports/first-bowl/preview.html`, тексты форматов и копии реальных фотографий,
а также `commerce.json` с безопасной выборкой товарных ссылок/ID. Для формата ВК дополнительно
создаётся `vk.json` с текстом, CTA, порядком фото, `vk_product_id`, связанными товарами и
предложенными UTM-ссылками `vk/social/<slug>`. Уже существующие `utm_*` не перезаписываются.
Команда export не вызывает API ВК.
В превью установлен `noindex,nofollow`. Оно локальное; публичного действия нет.

Следующий ручной маршрут нужен только при просьбе о ручной вычитке. Для прямого выпуска
используйте `vk publish` или `publish --request`.

Человек проверяет превью и `review.json`: указывает своё имя, комментарии, отмечает
проверенные разделы и рассмотренные предупреждения. Из вывода `status` копируется **полный**
`confirmation_token`. Его нужно подставить в следующую команду вместо многоточия:

```bash
python bamboo.py approve first-bowl --confirm "first-bowl@..."
```

Правка текста, источников, паспорта товара, фото, конфигурации, образцов голоса или рецензии
делает прежнее утверждение недействительным. После правки нужна повторная проверка и обновление
`content_hash` в рецензии. Модель не должна сама проставлять человеческие отметки.
Хеш — контроль версии, а не электронная подпись личности.

## Публикация

```bash
# Только план, без сети:
python bamboo.py publish first-bowl --channel wordpress
# После настройки доступа: настоящий черновик в WordPress
python bamboo.py publish first-bowl --channel wordpress --execute
# Публичная запись требует отдельного явного действия и текущего токена:
python bamboo.py publish first-bowl --channel wordpress --execute --live --confirm "first-bowl@..."
# Альтернатива: собрать статический сайт локально
python bamboo.py publish first-bowl --channel static --execute
```

WordPress требует `wordpress_url` в `bamboo.json` и переменные окружения
`BAMBOO_WP_USER`, `BAMBOO_WP_APP_PASSWORD` — application password, не обычный пароль аккаунта.
Перед первым рабочим запуском проверьте интеграцию на тестовом сайте. Используется HTTPS.
После неопределённого сетевого ответа отправка блокируется до `wp-reconcile first-bowl`
либо ручного разбора; повторный POST вслепую не выполняется.

Статический режим создаёт `site/` с HTML, canonical, sitemap.xml и robots.txt.
Нужен собственный `site_url`. **Загрузка на хостинг не выполняется.**
Для ВКонтакте остаётся локальный экспорт. Для отправки утверждённого пакета через API:
`python bamboo.py vk plan-post first-bowl --request "Опубликовать утверждённый пакет"`,
для прямого поручения проще `vk publish`; ручной маршрут — `vk apply`. [Порядок](docs/VK_STORE.md).

## Аналитика

```bash
python bamboo.py analytics-import --file your-metrics.csv
python bamboo.py analytics-pull --provider google --start 2026-09-01 --end 2026-09-14
python bamboo.py analytics-pull --provider yandex --start 2026-09-08 --end 2026-09-21
python bamboo.py analytics-report --end 2026-09-14 --days 7
# Опционально: квотируемая расширенная Яндекс URL×query выгрузка
python bamboo.py analytics-yandex-export-dates
python bamboo.py analytics-yandex-export-start --date 2026-09-20 --path /journal/chawan/
python bamboo.py analytics-yandex-export-status <task-uuid>
# После скачивания готового β-CSV:
python bamboo.py analytics-yandex-import --file yandex-url-query.csv

# Проверка коммерческого графа:
python bamboo.py commerce-build
```

Даты — примеры синтаксиса, замените на нужный доступный период.
Google: Search Console `page` и точный `page_query`, с пагинацией.
Яндекс: Query Analytics отдельно по URL и QUERY за доступные последние две недели. Для QUERY
связанный URL хранится только как `page_hint`: это не полная разбивка запрос × страница.
Отчёт показывает запросы, словарные query-кластеры, intent-hints, кандидатов на несколько URL,
intent mismatch, отдельные conversion-метрики и воронку только при явном совпадении источника.
CSV допускает подтверждённые переходы к товару, обращения, заказы, выручку и затраты с grain=`conversion`.
Повторный импорт обновляет строки, не удваивает их; пропуски не становятся нулями.
Отчёт предлагает изменения, но **не переписывает стратегию, статьи и правила автоматически**.
Расширенный Яндекс CSV импортируется как точный `yandex_enhanced/page_query`, сохраняя
региональную детализацию отдельно. `commerce-build` строит `content/commerce-graph.json`
с кластерами, связями и предложениями внутренней перелинковки.
Настройка доступа и ограничения: [аналитика](docs/ANALYTICS.md).

```text
AGENTS.md / CLAUDE.md / GEMINI.md   точки входа
skills/                            7 канонических сценариев
agents/                            6 канонических ролей
.agents/skills/                     Codex + Antigravity
.codex/agents/                      нативные TOML-роли Codex
.claude/skills/ и .claude/agents/    Claude Code
.agents/agents/ и .agents/rules/    Antigravity 2.0 / CLI
bamboo/                            Python CLI, проверки, публикация, аналитика
bamboo/vk/                         VK API, планы, авторизация, журнал и MCP
examples/                          шаблоны, не фактический каталог и не реальные метрики
docs/                              процесс, словарь предметной области, commerce-модель, аналитика
evals/                             поведенческие кейсы маршрутизации и редакционных ограничений
tests/                             проверки без внешних сервисов
```

Файлы адаптеров генерируются из канонических скиллов и ролей:

```bash
python tools/sync_adapters.py
python tools/sync_adapters.py --check
python tools/check_evals.py
python -m unittest discover -s tests -v
```

CI проверяет Python 3.10–3.13 на Linux, а также 3.12 на Windows и macOS.
Контрактные тесты HTTP используют подменённые ответы, не реальные аккаунты.
Нативный запуск внутри всех трёх ИИ, OAuth на ваших ресурсах и публикацию на вашем сайте
нужно проверить в соответствующей среде; наличие файлов не доказывает успешный запуск сервиса.
