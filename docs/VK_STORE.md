# Магазин ВК: управление через разговор с агентом

Локальный модуль для Python 3.10+, без сторонних библиотек, Docker, собственного
домена и сервера модели. Текст и решения готовит ваш ИИ в Codex, Claude Code или
Antigravity. Код читает VK API, проверяет план, выполняет разрешённые изменения и
сверяет результат. Сам по себе Python не является чат-ботом и не вызывает платную модель.

## Прямой выпуск готового поста

`python bamboo.py vk publish SLUG --request "Фактическое поручение владельца" --execute`
или MCP `vk_publish`. Прямое поручение достаточно; повторные ручные review.json/approve
не нужны. Без execute — без сети. Подробнее: [Публикация](PUBLISHING_POLICY.md).
Следующие ниже plan/show/apply остаются для точечных правок и запрошенной ручной вычитки.
Их хеши — технический контроль версии, а не требование повторять разрешение.
Нативная статья ВК не создается через wall.post; `--format article` в старом plan-post —
только текст статьи на стене. Не выбирать этот режим вместо родного редактора статей.

## 1. Подключить магазин один раз

Откройте папку репозитория на своём компьютере. В примерах `python3` — установленный
Python 3.10+. В Windows используйте `py -3`.

### Быстрый и надёжный способ (токен администратора через VK API)

Для управления товарами сообщества ВКонтакте требует **пользовательский ключ (User Access Token)
с ролью администратора или редактора** сообщества.

1. **Инициализируйте конфигурацию** (укажите короткое имя вашего сообщества):
   ```bash
   python3 bamboo.py vk init --community bamboopottery
   ```
   Команда создаёт локальную конфигурацию `.bamboo/vk/config.json` без сетевых вызовов.
   Если конфигурация уже существует, повторный `init` не требуется.

2. **Получите ключ доступа администратора через шлюз авторизации ВК**:
   Откройте в браузере под аккаунтом владельца/администратора сообщества ссылку авторизации
   с официальным клиентом `vk.com` (ID `6287487`):
   ```text
   https://oauth.vk.com/authorize?client_id=6287487&scope=market,photos,groups,wall,offline&redirect_uri=https://oauth.vk.com/blank.html&response_type=token&v=5.199
   ```
   *(При недоступности домена vk.com можно использовать зеркало `oauth.vk.ru`).*

3. **Разрешите доступ и скопируйте ключ**:
   В появившемся окне подтвердите доступ (товары, фотографии, группы, стена и бессрочный доступ).
   Браузер перейдёт на пустую страницу `blank.html`. В адресной строке будет адрес:
   ```text
   https://oauth.vk.com/blank.html#access_token=vk1.a.ВАШ_КЛЮЧ...&expires_in=0&user_id=...
   ```
   Скопируйте значение ключа — всё от `access_token=` до следующего знака `&` (ключ начинается на `vk1.a.`).
   *Никогда не публикуйте ключ в репозитории и не отправляйте его в чат.*

4. **Импортируйте ключ локально в терминале**:
   ```bash
   python3 bamboo.py vk token-import
   ```
   Вставьте скопированный ключ в скрытый запрос терминала (ввод скрыт, курсор не двигается) и нажмите Enter.
   Ключ сохранится в защищённый файл `~/.config/bamboo/vk-token.json` вне проекта с правами 0600.

5. **Проверьте связь и загрузите данные**:
   ```bash
   python3 bamboo.py vk check
   python3 bamboo.py vk sync
   ```
   `check` определяет числовой ID сообщества, пользователя, роль и доступность чтения.
   В ответе должно быть `admin_level: 3` (или `2`), а для `store.get`, `product.list` и `post.list` —
   статус `read_ok`. Он НЕ создаёт тестовый товар/пост и НЕ доказывает права записи.
   `sync` получает товары и подборки с пагинацией и последние 100 записей со стены.

### Альтернатива: собственное приложение VK ID и диагностика ограничений

Если вы регистрируете собственное приложение через [кабинет VK ID](https://id.vk.com/about/business/go):

```text
Название: Bamboo VK Manager
Платформа: Web
Базовый домен: localhost
Доверенный Redirect URL: http://localhost/vk/callback
```

```bash
python3 bamboo.py vk init --community bamboopottery --client-id 12345678
python3 bamboo.py vk login
```

`login` запускает локальную авторизацию PKCE: открывает окно входа, ожидает редирект на localhost,
валидирует state, code_verifier и обменивает одноразовый код на токены.

**Диагностика типичных ошибок платформы ВКонтакте:**
* **VK 1051 (Method is not available for this profile type):** Кабинет VK ID предназначен для
  аутентификации пользователей на сайтах (имя, email, телефон) и не выдаёт права `market` новым Web-приложениям.
  При авторизации через `id.vk.com` токен урезается до `vkid.personal_info`, а вызовы `market.*` блокируются.
* **VK 27 (Group authorization failed: method is unavailable with group auth):** Создание «Ключа доступа
  сообщества» в настройках группы (*Управление → Дополнительно → Работа с API*) не позволяет управлять витриной:
  ВКонтакте на уровне API запрещает методы `market.*` для ключей сообщества, требуя токен пользователя.
* **VK 9 (Flood control):** Старые неофициальные ID приложений (например, Kate Mobile `2685278`)
  глобально заблокированы платформой ВКонтакте и возвращают ошибку лимита на любые запросы.
* **Security Error / invalid_request:** Возникает при попытке запросить Implicit Flow (`response_type=token`)
  для Web-приложения VK ID либо при рассинхронизации сессионных cookie в браузере.

### Где находятся ключи

По умолчанию: `~/.config/bamboo/vk-token.json`, вне проекта; POSIX-права 0600.
Авторизация PKCE сохраняет refresh_token и обновляет его при ротации. Секреты не
выводятся в результат команд/MCP и не вставляются в URL вызовов методов VK API.
Приоритет имеет переменная `BAMBOO_VK_ACCESS_TOKEN`. Для другого защищённого файла
задайте `BAMBOO_VK_TOKEN_FILE` абсолютным путём вне рабочего проекта.

Хранилище не является зашифрованным сейфом. На Windows проверьте права ACL;
на всех ОС не давайте другим пользователям читать профиль. ИИ с неограниченным
shell от вашего имени технически способен прочитать ваши файлы: для строгой
изоляции ограничьте инструменты агента интерфейсом MCP, запретите чтение ключей
и оставьте ручное подтверждение `vk_apply`. При компрометации отзовите разрешение
приложения в ВК; простое удаление локального файла не отзывает серверный доступ.

## 2. Общаться с агентом

Откройте проект в выбранной среде ИИ, обновите список навыков/перезапустите сессию.
Скажите:

> Используй bamboo-vk-store. Проверь подключённый магазин и покажи товары.
> Пока ничего не изменяй.

Дальше — обычные поручения, например:

> Найди чашу по артикулу, покажи её ID и текущую цену. Подготовь изменение цены на 2700 рублей.

> Подготовь снятие с продажи вот этих двух товаров. Покажи список и что изменится.

> Подготовь публикацию утверждённого пакета first-post с его фотографиями.

> Измени описание сообщества на следующий текст. Другие параметры не трогай.

Агент сначала читает фактические данные, затем показывает before/params и полный
confirmation. При прямом точном поручении агент проверяет версию и выполняет ее без повторного вопроса; иначе владелец сначала определяет изменения.
После этого агент вызывает apply и сообщает статус по каждому действию. Не включайте
режим автоматического одобрения всех инструментов. Наличие скилла не заменяет
выданные приложению права и подключение локального исполнителя.

Роли: координатор использует `bamboo-vk-store`; `bamboo-vk-reviewer` независимо
проверяет план на чтение; существующие factcheck/editor проверяют факты и текст.
Субагенты не имеют права утверждать изменения от имени владельца. Если среда не
умеет запускать субагентов, проверки выполняются последовательно без имитации делегирования.

## 3. Что реализовано

| Объект | Операции |
|---|---|
| Товары | Чтение, поиск, создание, изменение, снятие/возврат через deleted, удаление |
| Поля товара | Название, описание, цена/старая цена, категория, артикул, остаток, размеры, вес, фото, заданные ID видео/вариантов и ссылка |
| Подборки | Чтение, создание, название, основной/скрытый статус, существующий ID обложки, удаление |
| Записи | Чтение, публикация, редактирование, удаление, закрепление/открепление, отложенная публикация |
| Фотографии | JPG/PNG: загрузка для товара и стены; ссылки на результат в одном плане |
| Сообщество | Название, описание, короткий адрес, сайт, доступные настройки разделов, магазина, валюты и контакта продавца |
| Дополнительно | Категории, статистика при выданных правах; история выполнения и сверка после ошибки |

Точный разрешённый список полей и типов: `python3 bamboo.py vk operations`.
Идентификаторы берите из ответа ВК, не выдумывайте. Для product.create поле name
отправляется в API, а при чтении имя приходит как title. Цена передаётся в основных
единицах валюты магазина; `price.amount` из VK возвращается в сотых долях.

Не реализованы: заказы и персональные данные покупателей, рассылки/личные сообщения,
платежи, реклама, смена владельца/администраторов, пароль/2FA, загрузка видео,
загрузка обложки подборки, перенос товаров между подборками и параметры без
доступного публичного метода. Не обещайте «весь личный кабинет».
Некоторые редкие поля VK не возвращает в точечном чтении. Запись такого поля
может получить статус `unverified`; это не основание заявлять успех или повторять запись.

## 4. Изменение вручную через CLI

```bash
python3 bamboo.py vk read product.list --params '{"count":100}'
python3 bamboo.py vk read product.get --params '{"item_id":123}'
python3 bamboo.py vk read categories --params '{"count":100}'
python3 bamboo.py vk read store.get
python3 bamboo.py vk read post.list --params '{"filter":"postponed","count":100}'
```

Все ID в примерах учебные. Замените их на реальные, полученные из своего магазина.
Сохраните `content/vk-request.json`:

```json
{
  "request": "Изменить цену выбранного товара 123 на 2700 рублей; остальные поля сохранить",
  "actions": [
    {"operation": "product.update", "params": {"item_id": 123, "price": "2700.00"}}
  ]
}
```

```bash
python3 bamboo.py vk plan --file content/vk-request.json
python3 bamboo.py vk show PLAN_ID
# Только предпросмотр, без сети:
python3 bamboo.py vk apply PLAN_ID
# После проверки соответствия конкретному поручению (либо запрошенной ручной вычитки):
python3 bamboo.py vk apply PLAN_ID --confirm 'vk:PLAN_ID:ПОЛНЫЙ_SHA256' --execute
python3 bamboo.py vk history
```

`PLAN_ID` и полный confirmation копируются из результата plan/show, а не создаются
вручную. План живёт один час. Для существующего объекта требуется сохранённое
чтение не старше суток; перед выполнением код заново читает объект и сравнивает
редактируемые поля. Конфликт требует нового снимка и нового подтверждения.
Один объект редактируется не более одного раза в плане. Массовый план — до 50
действий с конкретными ID; скрытых «все товары» или вычислений цены нет.

### Новый товар с фото

Положите свою фотографию в `content/media/cup.jpg`. Подтвердите характеристики и
категорию; `100` ниже — условный ID, не рекомендация для керамики.

```json
{
  "request": "Создать согласованную карточку с выбранной фотографией",
  "actions": [
    {"operation": "photo.product", "params": {"file": "content/media/cup.jpg", "main_photo": true}},
    {"operation": "product.create", "params": {
      "name": "Название из паспорта изделия",
      "description": "Подтверждённое владельцем описание изделия.",
      "category_id": 100, "price": "2700.00", "main_photo_id": "$0.photo_id"
    }}
  ]
}
```

`$0.photo_id` — результат первой операции именно этого плана. Для постов используются
`photo.wall` и массив `attachments: ["$0.attachment"]`. Ссылки вперёд, неверный тип,
выход за content/media, подмена файла после просмотра и символические ссылки запрещены.
Локальные пределы: 20 МиБ на фото, 50 МиБ на план. Проверяются расширение, сигнатура
и SHA256, но не художественное качество изображения и не соответствие изделия фото.

### Публикация существующего контент-пакета

Сначала обычные `validate`, `export`, рецензия и `approve` для пакета. Затем:

```bash
python3 bamboo.py vk plan-post first-post --request "Опубликовать утверждённый first-post в магазине"
```

Команда берёт точные текст/CTA/фото утверждённой версии. Весь план, включая загрузки,
повторно проверяет утверждение ДО первой записи. Изменение пакета аннулирует план.
Дополнительный аргумент `--publish-date` принимает будущее Unix-время. Укажите агенту
дату, время и часовой пояс явно; программа не угадывает часовой пояс по языку.
`publish --channel vk` не добавлен: редакционная публикация ВК идёт через `vk plan-post`.

## 5. MCP: подключение инструментов к локальному ИИ

MCP не обязателен для агента с разрешённым CLI. Для клиента MCP запустите как
stdio-процесс команду `python3 /ПОЛНЫЙ/ПУТЬ/bamboo.py --workspace /ПРОЕКТ vk mcp`.
stdout занят JSON-RPC; сервер не открывает сетевой порт и не выдаёт команды авторизации.
Пример конфигурации Claude Code: добавьте запись в mcpServers существующего `.mcp.json`,
не перезаписывая другие подключения:

```json
{
  "mcpServers": {
    "bamboo-vk": {
      "type": "stdio",
      "command": "python3",
      "args": ["/ПОЛНЫЙ/ПУТЬ/bamboo.py", "--workspace", "/ПРОЕКТ", "vk", "mcp"]
    }
  }
}
```

Для Codex добавьте отдельный раздел в конфигурацию, сохранив остальные настройки:

```toml
[mcp_servers.bamboo_vk]
command = "python3"
args = ["/ПОЛНЫЙ/ПУТЬ/bamboo.py", "--workspace", "/ПРОЕКТ", "vk", "mcp"]
default_tools_approval_mode = "prompt"
```

Пути замените на существующие абсолютные. На Windows укажите полный путь к python.exe
или command="py" и добавьте "-3" первым аргументом. Токены в JSON/TOML не вставляйте.
Не включайте bypassPermissions/автоматическое разрешение `vk_apply`.

Инструменты: vk_status, vk_operations, vk_check, vk_sync, vk_read, vk_plan,
vk_plan_post, vk_show, vk_apply, vk_reconcile. У vk_apply по умолчанию execute=false.
Версии протокола: 2025-06-18, 2025-03-26, 2024-11-05; интерфейс tools/stdio,
без resources/prompts и удалённого HTTP. Это локальный сервер, а не автоматическое
подключение к текущему чату ChatGPT. Нативное подключение проверяется в вашем клиенте.

## 6. Ошибки и восстановление

`5`: ключ недействителен/истёк — повторите локальный вход. `7/15/27`: проверьте роль,
тип ключа, разрешения приложения и метод. `14`: требуется подтверждение ВК; не
обходите его. `100`: проверьте поля по vk operations и актуальной документации.
Сервисный ключ и ключ сообщества не заменяют пользовательский доступ ко всем методам.

Каждой отправке предшествует сохранение состояния `sending`, затем сохраняется ответ
`written`, затем выполняется чтение. `verified` означает успешную сверку; для фото —
полученный ID сохранения, не визуальную проверку. `unverified`/`uncertain`/оставшийся
после аварии `sending` блокируют повтор. HTTP-перенаправления запрещены, ошибки не
печатают необработанное тело с токенами. Только чтения повторяются при коде 6.

```bash
python3 bamboo.py vk reconcile PLAN_ID
```

Сверка ничего не изменяет и не снимает запрет повторной отправки. При потерянном
ID создания/загрузки нужна ручная проверка ВК. Успешные предыдущие действия не
откатываются: VK не предоставляет транзакцию на весь такой план. После ручной
сверки сохраните вывод, обновите снимок и создайте отдельный план ТОЛЬКО для
действительно оставшихся изменений. Не удаляйте журнал ради повтора.

Откат — отдельная подтверждаемая операция по полям before, а не обещание восстановить
удалённый товар или пост. Между чтением и записью остаётся гонка: VK API не предоставляет
атомарное условное обновление этих объектов. Локальная блокировка защищает этот
рабочий проект, но не другого администратора или другой компьютер.

Рабочие файлы `.bamboo/vk/config.json`, snapshot.json, plans/, receipts/ игнорируются
Git. Они содержат фактические данные магазина; не отправляйте их в публичные отчёты
целиком. Журнал имеет локальную защиту правами файлов, но не криптографическую защиту
от самого пользователя ОС. Хеш подтверждения — контроль версии, не подпись человека.
