# Первый рабочий материал

## Минимум

Python 3.10+ и любая поддерживаемая ИИ-среда. Никаких pip install, сервера или новых подписок.
Рабочая папка должна быть локальной. Все команды выполняйте из неё.

```bash
python bamboo.py init
python bamboo.py doctor --text
```

Диагностика не ходит в сеть и не меняет файлы. Она показывает статусы заданий, наличие
образцов голоса и границы сохранённых измерений. Наличие OAuth-переменной не означает,
что доступ проверен. JSON-режим остаётся доступен без --text.

## Один пост, один товар

Для общего поста паспорт необязателен. Для конкретного изделия скопируйте
examples/product.template.json в content/products/<id>.json. В установленном проекте
шаблон находится в .bamboo/toolkit/examples/. Заполните известные факты; неизвестные
оставьте null. Только владелец подтверждает confirmed, права на фото и разрешение на фактуру.
В content/voice/ можно добавить разрешённые публичные тексты мастера: это образцы, не готовое
доказательство, что модель воспроизводит его голос. README.md не считается образцом.

```bash
python bamboo.py new first-post --topic "Тема из ваших фактов" --formats vk
```

Для товара добавьте --products <id>. Набор форматов выбирайте под задачу: карточке не нужна
статья-предшественник. По умолчанию создаётся один формат vk.

Задание выбранному ИИ:

> Используй bamboo-content для first-post. Проверь бриф и разрешённые источники.
> Собери неизвестные сведения одним сообщением. Подготовь один пост ВК и превью всех
> запрошенных форматов. Не выдумывай опыт мастера, не утверждай и не публикуй за человека.

```bash
python bamboo.py validate first-post
python bamboo.py export first-post
```

Ожидается exports/first-post/preview.html, тексты и фото. В смешанном пакете превью должно
показывать все форматы, а не только статью. Ошибка validate — повод исправить конкретный
факт/источник/поле, а не автоматически снять ограничение.

## Проверка человеком

Используйте review-template, status и approve по docs/WORKFLOW.md. Не проставляйте человеку
галочки автоматически. Утверждение привязано к версии текста, фактов, фото и политик,
включая машиночитаемый словарь. Публикация — отдельное явное поручение; для ВК выдаётся
локальный пакет, а не сообщение об успешной отправке.

## Аналитика без лишней настройки

Начните с одного реального файла. CSV универсального формата — analytics-import;
расширенный Яндекс URL×query CSV — analytics-yandex-import. Источники и регионы не
складываются как разные независимые аудитории. Исходную выгрузку храните отдельно.

```bash
python bamboo.py analytics-report
```

В analytics/report.md сначала идут до трёх действий, затем исходные метрики. В JSON:
latest_dates — даты сохранённых источников; metric_coverage — заполненность каждой метрики;
opportunities — основания, ограничения и критерии проверки. Нет данных — нет выдуманных тем.
По умолчанию последняя дата в базе. --end и --days нужны только для явного выбора периода.

Импорт не означает проверку OAuth. Полнота строк не означает полноту поискового API.
Отношение orders/clicks не доказывает, что эти люди пришли и купили из этой же статьи.

## Проверка установки

В репозитории: python -m unittest discover -s tests -v. В CI выполняется тот же набор,
включая отдельный сквозной тест установленного проекта. Тестовые факты и метрики искусственные;
они не подтверждают продажи, авторизацию или качество модели. Проверка запуска навыков внутри
Codex/Claude/Antigravity описана в docs/EVALS.md и требует самой среды.
