# Данные и обратная связь

Настройки находятся в `bamboo.json.analytics`. Секреты — только переменные окружения;
программа не читает `.env` автоматически. В PowerShell задавайте `$env:NAME="значение"`,
в shell — `export NAME="значение"`. Не вставляйте секреты в задания модели, Git или логи.

## Google Search Console

`gsc_property`: точное подтверждённое свойство, например `sc-domain:example.org` или URL-prefix.
В Google Cloud включить Search Console API, настроить OAuth-клиент и согласие владельца,
дать scope `https://www.googleapis.com/auth/webmasters.readonly`.
Получение первого согласия/refresh-token выполняется штатным OAuth-процессом, не внутри скилла.

Поддерживается готовый `BAMBOO_GSC_ACCESS_TOKEN`, либо набор
`BAMBOO_GSC_CLIENT_ID`, `BAMBOO_GSC_CLIENT_SECRET`, `BAMBOO_GSC_REFRESH_TOKEN`.
Во втором случае CLI обновляет access-token запросом к официальному token endpoint.
Истёкший access-token, если он задан, не подменяется молча другим аккаунтом: уберите его
для использования refresh-набора. Авторизованный аккаунт должен иметь доступ к свойству.

Выгружаются `date,page` и отдельно `date,page,query`, type=web, dataState=final,
до 25 000 строк на страницу с startRow. У API есть собственные ограничения полноты и приватности.
Дни GSC определены в Pacific Time. Обычно выбирать завершённый период с запасом на задержку,
а не требовать итоговые показатели за текущий день. Сравнение используется внутри одного источника;
Google и Яндекс не суммируются в «точное количество уникальных людей».

## Яндекс.Вебмастер

`yandex_user_id` и `yandex_host_id` взять из официального API под своей OAuth-авторизацией,
после подтверждения прав на сайт. `BAMBOO_YANDEX_TOKEN` — токен приложения с доступом к Вебмастеру.
Используется метод v4 query-analytics/list, группировка URL, ALL devices, WEB_LOCATION,
500 строк на страницу. Даты фильтруются локально: метод отдаёт последние две недели,
а не произвольный архив. Частые выгрузки накапливают свою историю в SQLite.

`popular_complementary_indicator` — популярный связанный запрос, **не** распределение всех
кликов URL по запросам. Он намеренно не превращается в page_query. Отсутствующий показатель
сохраняется NULL, а не нулём. В `pull-yandex.json` зафиксированы границы запроса и ограничения.

## Унифицированный CSV

Обязательные заголовки: `date,source,grain,page,query`.
Метрики: `impressions,clicks,position,product_clicks,leads,orders,revenue,cost`.
Пустая ячейка означает «не измерено». Нулевое значение — измеренный ноль.
Финансовые значения в одной выгрузке должны быть в одной заранее согласованной валюте;
конвертация валют и бухгалтерский расчёт прибыли не выполняются.

`grain=page` — итоги страницы; `page_query` — детализация; `conversion` — собственная
атрибуция обращений/заказов. Нельзя присваивать один и тот же заказ нескольким источникам
как независимые продажи. Удалите имена, телефоны, email и тексты переписки покупателей.
В импортируемых URL/запросах тоже не должно быть персональных данных.

Ключ SQLite — `(date,source,grain,page,query)`. Повторный импорт делает upsert.
Дубликаты ключа внутри одной выгрузки, NaN, отрицательные метрики и неверные даты отвергаются
до записи всего набора. Источник не обязан иметь строку за каждый день: отсутствие строки
не считается измеренным нулём. Автоматического удаления уже импортированных строк нет.
Изменение состава выгрузки требует отдельного осознанного исправления локальной базы.

## Отчёт и решения

Отчёт сравнивает два соседних равных периода. Отдельно группирует источник, детализацию и страницу;
page_query не прибавляется к page. CTR вычисляется из сумм кликов и показов; позиция взвешивается
показами. Рост кликов выводится только при полной дневной представленности обоих периодов
и ненулевой базе. Это всё равно не доказательство причинности и не измерение всей полноты API.

Порог min_impressions — эвристика, по умолчанию 100. Низкий CTR — повод проверить позицию,
устройство, брендовый спрос, заголовок и совпадение намерения, а не автоматическая команда переписать H1.
Нет продаж в отчёте без фактической conversion-выгрузки. Страницы с малой выборкой не удаляются.
`bamboo-analyst` предлагает одну проверяемую гипотезу, метрику, срок и откат.
Владелец утверждает её в `content/strategy.md`; агент не изменяет свою политику самостоятельно.

## Регулярный запуск

Планировщик не устанавливается и ничего не активируется при установке.
Один проход можно выполнить `python tools/weekly.py --workspace /путь --provider google --end YYYY-MM-DD`.
Этот скрипт берёт 14 дней, затем строит два семидневных периода, не вызывает модель и не публикует.
В установленном проекте его путь `.bamboo/toolkit/tools/weekly.py`.
Добавьте эту команду в собственный cron/systemd timer или Windows Task Scheduler с рабочим каталогом
проекта и безопасно переданным окружением. Для Яндекса не откладывайте сбор за пределы двухнедельного окна.
Для Google параметр end можно опустить: используется UTC-дата минус четыре дня как консервативная
эвристика задержки, не гарантия готовности. Для Яндекса по умолчанию вчера по UTC.
