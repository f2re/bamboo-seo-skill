# Коммерческая SEO-модель Bamboo Pottery

Контент не должен существовать отдельно от реального ассортимента. Базовая модель:

```text
категория/коллекция
  ├─ конкретные изделия
  ├─ техника/термин
  └─ экспертные материалы
        └─ релевантный переход к категории, изделию или вопросу мастеру
```

## Типы страниц

- **product** — один подтверждённый экземпляр/товар; характеристики только из паспорта.
- **category** — группа реальных товаров: тяваны, пиалы, чайники, коллекция/техника.
- **article** — отвечает на информационный или исследовательский вопрос и ведёт к релевантной
  категории/изделию, если оно реально есть.
- **technique/term** — справочная сущность; не должна конкурировать с товарной страницей
  по чисто коммерческому намерению.
- **social** — ВК/сторис/карусель; не считается самостоятельной индексируемой SEO-страницей.

## Граф связей

Для каждой индексируемой страницы фиксировать:

- `page_type`;
- `cluster` — например `kurinuki`, `chawan`, `yixing-teapot`;
- главный пользовательский вопрос;
- связанный product/category;
- исходящие внутренние ссылки;
- CTA;
- измеряемое действие: product_click / lead / order.

Одинаковый ключ не означает одинаковое намерение. Одинаковое намерение у нескольких URL —
повод проверить объединение/перелинковку, а не автоматически удалять страницу.

## Карточка товара

Минимум: ID, название/тип, подтверждённые материал/техника/размеры/объём при наличии,
фото, авторство, цена/наличие если актуальны, ссылка на товар и источник характеристик.
Неизвестное остаётся `null`.

Расширенный шаблон: `examples/product.template.json`.
Шаблон категории: `examples/collection.template.json`.

## Внутренние ссылки

Статья не должна заканчиваться одинаковым рекламным абзацем. Ссылка выбирается по намерению:

- вопрос о выборе → категория или подходящие товары;
- техника → изделия, реально выполненные в этой технике;
- уход → только изделия, к которым рекомендации применимы;
- подарочный сценарий → актуальная подборка, а не несуществующий ассортимент.

`bamboo-seo` проверяет эту связь до публикации.


## Автоматический аудит графа

```bash
python bamboo.py commerce-build
```

Команда читает подтверждённые паспорта из `content/products/`, коллекции из
`content/collections/` и SEO-контекст задач. Результат — `content/commerce-graph.json`:

- узлы product / collection / job;
- связи collection→product и content→product;
- кластеры;
- дубли `target_url`;
- отсутствующие товары/коллекции;
- предложения внутренней ссылки, если статья связана с product_id, но URL товара не указан.

Это аудит, а не автоматическое редактирование текста.

## Product / Offer structured data

Bamboo не добавляет `Product` на статью просто потому, что в ней упомянут товар. Для merchant
listing нужна собственная страница, на которой покупатель действительно может приобрести
конкретный товар. `commerce-build` лишь рассчитывает `structured_data_candidates`.

Кандидат требует как минимум собственной product_url на домене `site_url`, названия,
публичного URL изображения, цены, валюты и наличия. Внешняя карточка ВК или другого магазина
не превращает статью Bamboo в merchant product page. Фактическую Product/Offer-разметку
генерировать только при появлении собственной страницы покупки и после отдельной проверки.


## ВК и измеряемый переход

При экспорте формата `vk` создаётся `vk.json`. Для каждого подтверждённого `product_url`
инструмент предлагает ссылку с `utm_source=vk`, `utm_medium=social`,
`utm_campaign=<slug>`. Если URL уже содержит любую `utm_*`, исходная разметка сохраняется.

Также фиксируются порядок вложений и доступные `vk_product_id`. Это позволяет связывать
ручную публикацию с последующим `conversion`-импортом, не давая инструменту права самостоятельно
размещать пост или приписывать заказ источнику.
