# Интеграции с ИИ

Контракты сверены с официальной документацией 21 сентября 2026 года; ссылки в SOURCES.md.
Устанавливается только проектный набор. Домашние конфиги, выбор модели и разрешения пользователя
не меняются. Это не пакет подписок и не автономный планировщик ИИ.

| Среда | Скиллы | Агенты | Инструкции |
|---|---|---|---|
| Codex | `.agents/skills/*/SKILL.md` | `.codex/agents/*.toml` | `AGENTS.md` |
| Claude Code | `.claude/skills/*/SKILL.md` | `.claude/agents/*.md` | `CLAUDE.md` импортирует `@AGENTS.md` |
| Antigravity 2.0 / CLI | `.agents/skills/*/SKILL.md` | `.agents/agents/*.md` | `.agents/rules/bamboo.md`, `GEMINI.md`, `AGENTS.md` |

Общие `.agents/skills` создаются один раз, не дублируются при выборе Codex + Antigravity.
Исходный сценарий находится в `skills/`, нативный SKILL.md — короткая точка входа. Благодаря
этому агент не загружает все материалы заранее. Установка в иной проект меняет пути ссылок
на `.bamboo/toolkit/`; относительные пути к рабочему контенту остаются прежними.

## Codex

Вызовите скилл по имени через интерфейс или сформулируйте «используй bamboo-content».
Роли задают name, description, developer_instructions и sandbox_mode=read-only.
Модель наследуется из среды. Не включается обход подтверждений. Возможность запуска ролей
зависит от доступности субагентов и настроек конкретной версии. Ограничения вызывающей среды
могут влиять на разрешения дочерних агентов; файл роли не является отдельной границей безопасности.

## Claude Code

Команды `/bamboo-plan`, `/bamboo-research`, `/bamboo-content`, `/bamboo-review`,
`/bamboo-publish`, `/bamboo-analytics`. У публикации `disable-model-invocation: true`:
она не должна стартовать по инициативе модели. Контроль CLI действует дополнительно.
Подагенты получают только Read, Grep, Glob и model=inherit. Внешнее исследование и запуск
CLI выполняет координатор со штатными разрешениями, а не read-only проверяющий.

## Antigravity

Используется актуальное дерево `.agents`, а не обязательная зависимость от старого `.agent`.
Роли доступны в поддерживающих custom subagents версиях Antigravity 2.0 / CLI: mainAgent=false,
subagent=true, model=inherit; инструменты view_file и grep_search; shell execution выключен.
Не добавляются вымышленные названия инструментов или скрытые автозапускаемые workflow.
Скилл можно выбрать через интерфейс либо назвать в запросе.

В старом IDE без загрузки custom agents координатор читает канонические роли и выполняет их
последовательно. Это **не** независимые агенты. Если версия не подхватывает правило автоматически,
подключите `.agents/rules/bamboo.md` в разделе Rules и явно укажите прочитать AGENTS.md.
Не переносите эти настройки в глобальный профиль без отдельного решения владельца.

## Контракт делегирования

Координатор передаёт роль, slug, точные пути, конкретный вопрос, разрешённые источники и формат
отчёта. Не передавать всю историю, секреты и переписку клиентов. Изолированный агент не обязан
знать контекст предыдущих разговоров. Сначала три независимые проверки, затем при необходимости
повторная проверка затронутого участка. Результаты не объединяются голосованием: подтверждённый
фактический дефект блокирует публикацию, даже если остальные роли не возражают.

`doctor` лишь обнаруживает файлы и исполняемые команды. Графический Antigravity может работать
без команды `antigravity` в PATH. Это не ошибка установки скиллов.

## Проверка после установки в вашей среде

Открыть проект и начать новую сессию. Проверить видимость шести скиллов и пяти ролей.
Попросить bamboo-review разобрать демонстрационный незаполненный бриф — он должен сообщить
об ошибках, не выдумать факты. Проверить отказ публикации без утверждения.
Затем заполнить один реальный предмет и пройти полный цикл до черновика WordPress на тестовом сайте.
Ни API-тесты с подменёнными ответами, ни проверка файлов не заменяют этот приёмочный запуск.
